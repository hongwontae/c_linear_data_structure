1. 더미 헤드를 갖는 리스트로 변환
    1-1. 헤드 포인터 대신 더미 헤드 노드를 갖는 구조
    1-2. 헤드 노드는 항상 존재하므로 그 자체가 null일 가능성을 고려할 필요가 없습니다.
    1-3. 헤드 노드에 대한 포인터를 사용하는 방식에 비해 더 간단한 구조입니다.
    1-4. 지금까지 만들었던 링크드 리스트는 헤드 노드가 앞에 아무것도 존재하지 않기에 경우의 수를 하나 더 고려해서 구조를 설계했습니다.
        => 만약 앞에 더미가 있는 구조로 변경하면 경우의 수가 하나 줄어들고 복잡도도 떨어집니다.
    1-5. 더미 헤드 노드는 데이터가 없고 어떤 노드 앞에 존재할 목적으로 존재합니다.


2. 코드 전환
    2-1. USERDATA global_head_node = {...}
        => 더미 노드 자체를 생성하고 전역으로 둡니다.
    
    2-2. add_new_node (...) {}
        => 새로운 노드를 만들기 위해 동적 할당하고 값을 넣는 로직은 갖습니다.
        => 그 이후에 end_node를 찾아야 합니다. -> 이 떄 헤드 노드가 null인 가능성을 고려했어야 합니다.
        => 이제 헤드 노드는 반드시 존재하기에 head_node가 null일 가능성을 배제하고 end_node를 찾아서 넣어주면 됩니다.
    
    2-3. clear_node (){}
        => head_node는 동적 할당으로 만든 데이터가 아니고 전역에서 만든 데이터입니다.
        => clear_node의 목적은 동적 할당 해제이기에 clear_node의 head는 두 번쨰 노드부터 시작해야 합니다.
        => 즉, head_clear_node = global_head_node.p_next가 되어야 합니다.
        => 이후에 같은 로직이 반복됩니다.
        => 마지막에는 더미 노드의 p_next를 NULL로 바꿔줘야 합니다.
    
    2-4. print_node () {}
        => print_head_node가 받아야 하는 값은 더미 헤드 노드를 보여줄지, 더미 헤드 노드를 보여주지 않을지 결정하면 됩니다.
    
    2-5. USERDATA * search_by_name (const char * name) {}
        => search_head_node를 global_head_node.p_next로 주고 같은 로직을 사용합니다.
        => 해당 함수는 자료구조의 수정이 아니라 검색입니다.
